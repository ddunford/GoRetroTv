# Phase 1: Foundation

## Outcome
Every later phase can build, test, deploy and observe — and, critically, **can be checked against the
oracle from its very first instruction**. The checkpoint-hash machinery is infrastructure here, not a
later feature, because phase 2 has nothing to verify itself against without it.

## Overview
Go project skeleton, the development loop, CI, and the two things this project cannot be built
without: a bus/device architecture whose devices are serialisable from the first line, and the
oracle's tier-1 checkpoint hash on both sides.

## Custom Feature: the oracle harness

**Purpose:** The port's only independent correctness check (SPEC FR-6). No module covers it because
nothing like it exists outside this project.

**Shape (set by spike 002 — the naive per-instruction version is 1.8–59 GB per run):**
- **Tier 1** — a 32-bit state hash every 1,000 instructions, emitted by both implementations.
  447,000 checkpoints and 3.6 MB for a full cold boot; cheap enough for CI.
- **Tier 2** — on the first differing checkpoint, both sides re-run that 1,000-instruction window
  with full per-instruction tracing.

**Key patterns (non-obvious):**
- The hash must cover the **ISA mode bit**. Omit it and a MIPS16/MIPS32 divergence shows up as a
  wrong instruction rather than as a wrong mode, which sends the reader hunting the decoder.
- The dirty-RAM digest must be incremental, or hashing 32 MB every 1,000 instructions dominates.
- **The interval is a dial, not a constant** — 1,000 costs 3.6 MB, 10,000 costs 0.4 MB.

**Test checklist:**
- [ ] An injected divergence at a known instruction is localised to the correct 1,000-window
- [ ] Two identical runs produce byte-identical checkpoint streams
- [ ] The comparison refuses to report success over an empty or truncated stream
