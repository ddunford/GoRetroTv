# Phase 1: Foundation

## Outcome
Every later phase can build, test, deploy and observe — and, critically, **can be checked against the
oracle from its very first instruction**. The checkpoint-hash machinery is infrastructure here, not a
later feature, because phase 2 has nothing to verify itself against without it.

## Overview
Go project skeleton, the development loop, CI, and the two things this project cannot be built
without: a bus/device architecture whose devices are serialisable from the first line, and the
oracle's tier-1 checkpoint hash on both sides.

## Custom Feature: the oracle harness

**Purpose:** The port's only independent correctness check (SPEC FR-6). No module covers it because
nothing like it exists outside this project.

**Shape (set by spike 002 — the naive per-instruction version is 1.8–59 GB per run):**
- **Tier 1** — a 32-bit state hash every 1,000 instructions, emitted by both implementations.
  447,000 checkpoints and 3.6 MB for a full cold boot; cheap enough for CI.
- **Tier 2** — on the first differing checkpoint, both sides re-run that 1,000-instruction window
  with full per-instruction tracing.

**Key patterns (non-obvious):**
- The hash must cover the **ISA mode bit**. Omit it and a MIPS16/MIPS32 divergence shows up as a
  wrong instruction rather than as a wrong mode, which sends the reader hunting the decoder.
- The dirty-RAM digest must be incremental, or hashing 32 MB every 1,000 instructions dominates.
- **The interval is a dial, not a constant** — 1,000 costs 3.6 MB, 10,000 costs 0.4 MB.

**Test checklist:** (hand-maintained — these are the custom feature's own checks, not `TASK` ids, so
`scripts/bd-mirror-phases.py` does not manage them)
- [x] An injected divergence at a known instruction is localised to the correct 1,000-window
      — `statehash/compare_test.go::TestAnInjectedDivergenceIsLocalisedToItsWindow` (one bit of
      GPR7 from instruction 4,500,000; asserts the window is exactly 4,500,000–4,500,999 and that
      `Compared >= 4000`, so it cannot have stopped at line one).
- [x] Two identical runs produce byte-identical checkpoint streams
      — `statehash/statehash_test.go::TestTwoIdenticalRunsProduceIdenticalStreams`, with a
      ≥5-line guard so an empty stream cannot satisfy it vacuously. Measured on the real oracle
      too: two cold boots agree over a common 4,613 checkpoints / 461M instructions, with 4,934
      distinct hashes — so agreement is not the degenerate case of a constant hash.
- [x] The comparison refuses to report success over an empty or truncated stream
      — `statehash/compare_test.go::TestAnUnusableStreamIsAHarnessFailureAndNotAgreement` and
      `cmd/oraclecmp/main_test.go::TestAnUnusableStreamExitsTwoAndSaysSo`. Keyed off the **absence
      of the `END` trailer**, never line count. Verified by hand against the committed real boot:
      truncated → exit 2 "HARNESS FAILURE — nothing was compared"; empty → exit 2; intact → exit 0.
      Three distinct exit codes (0 agree / 1 diverge / 2 harness failure) keep "they disagreed"
      and "I could not tell whether they disagreed" from being the same answer.

**Built but not planned here, and worth knowing:** the emitters must sample at the *same instant*.
The oracle steps over about one boundary in ten (477 of 4,629 on the recorded boot, the first at its
fourth checkpoint) because its MIPS32 path retires a branch and its delay slot together. `oraclecmp`
therefore pairs by **window**, counts and names such a window, and **carries on** rather than
stopping — an early straddle used to end the walk before any machine state was compared at all.
