Why some keys are named and the rest are hex

THE SMALL NUMBER ON EACH KEY IS THE RAW COMMAND BYTE, and it is the only part of a key this firmware can prove. The native side translates raw bytes to logical codes and nothing more — the NAMES live in the EPG’s o-code. So keys whose effect has been measured on a settled box are named (sky, tv guide, interactive, standby, the arrows, select, back up, the digits) and the rest carry the logical code they resolve to. The colour strip is the conventional Sky order for layout only; which raw byte is red is not established, and pressing them is how to find out. The readout above is computed from the live tables at 0x800FCEC0 and 0x800FCEB4 rather than from a copy of them kept here.

Boot messages — the firmware’s own commentary

This box was shipped with its diagnostics compiled in, and the format strings are still in the flash. They are read at 0x8007D06C, whose prologue spills $a0–$a3 and $t0–$t3 — eight registers, which is how a MIPS o32 varargs function receives its arguments before it has to touch the stack — so the format is $a0 and the first seven arguments follow. Nothing here is our text: every line is the firmware describing itself. A cold boot says more than a warm one, because the loader only searches for the application when there is no NVRAM to short-circuit it.

Serial ports — watching the box talk

Two of the box’s three UARTs. Modem is 0xB2001000, the internal modem the start-up probes with AT. Card interface link is 0xB2002000 — not a console: a framed command protocol to the controller behind the box’s second card slot, which answers “no card” here. The main task blocks on every frame until the controller has clocked it out, so this link had to exist before the boot could continue.

Where it reaches now — the Nucleus PLUS scheduler

          
This emulator executes both instruction sets. The machine is an
            NEC VR4111 running Nucleus PLUS (the image says
            Copyright (c) 1993-1998 ATI - Nucleus PLUS - NEC4111): reset, vectors and
            low-level code are MIPS32, and the kernel and drivers are MIPS16 for density, reached
            through JALX. Those calls used to be skipped, which produced a phantom loop
            and three wrong diagnoses of the same halt. They are now taken, in both directions.

          
The path it walks: reset at 0xBFC00008 →
            0xBFC00408 → cache init → DRAM clear from a six-entry table →
            45 peripheral writes → four exception vectors installed →
            jalx 0xBFC0B444 (bus bring-up, MIPS16) →
            jalx 0xBFC0F7B4 = BOOTMain, which writes 1 to
            0x800083D4, calls 14 subsystem initialisers, writes 2, and
            hands off with jalx 0xBFC0DE08 — the RTOS scheduler.
            That is the bootloader’s real hand-off: not a loader, but “enter
            multitasking”, and it never returns.

          
One register is a deliberate fiction and is labelled as such. At
            0xBFC0B118 the MIPS16 code writes a command word and then polls
            0xB0009120 for bit 5, a completion flag. Real silicon sets it; nothing here
            does, so it spun a million times. That one register is modelled as always-complete and shown
            on the peripheral bus as modelled. The blanket alternative — answering
            0xFFFFFFFF so every status bit reads ready — would clear these loops and
            silently corrupt every value the firmware reads for its content rather than its
            flags.

          Some calls are skipped: this firmware is mixed MIPS32 and MIPS16e.
          The unknown opcode is JALX — it jumps, links, and switches instruction set.
          Its targets are in flash and aligned but do not decode as MIPS32, which is precisely what JALX
          means. Across the image 6,128 words carry that opcode, but only 16 have
          in-flash targets, and those resolve to 11 addresses of which four are not code at
          all — bytes inside compressed data that happen to decode as JALX.
          One target is 32 bytes of erased 0xFF; another is the ASCII text
          09-2-1. Two independent signals agree on which are real: every genuine call site
          sits in readable code below 0xC3000, and four of the seven surviving targets open
          with 0x63xx, a SAVE prologue. So it is seven routines, not
          eleven — an earlier version of this page said eleven, having counted the
          false positives. Whatever is still skipped is counted here:
          none yet.
